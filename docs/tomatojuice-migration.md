# 茄汁 / tomatojuice：安全启动、迁移与恢复

## 当前设计

**酒馆原生启动优先；桥接是可以失败的可选只读加速，不是启动条件。**

- HTML 中的 `script.js`、`scripts/i18n.js` 保留原生 URL；安装器不再写 import map 或核心模块代理 URL。修复旧 toolbox 入口时会恢复可核对的原始模块标签。
- 可选桥接使用 `async` 脚本，不阻塞 HTML 解析，也不保证抢在核心之前安装。晚到即只优化后续请求，不重放之前的请求。
- 仅尝试配置启用的 `/api/characters/all` 和 `/version` 只读 fast 路径。默认整个响应（包含 JSON 响应体）限时 2 秒，校验 HTTP 状态、JSON 类型及响应形状。404/500/502/503、断网、非 JSON、超时、旧 `ASYNC-MISS` 占位响应及 `STALE-ERROR` 均回退一次原生读取，随后 30 秒旁路。调用者取消不触发回退。
- 冷角色缓存默认采用 1.5 秒 fast 等待预算，超时返回 fast 错误，由桥接走原生读取；真实构建可在后台完成。`blockCharactersAllOnMiss: true` 是显式选择较长的 10 秒 fast 预算，同时浏览器预算为 11 秒（含传输、JSON 校验）；共享构建仍有独立的 10 秒期限。**绝不返回模拟空角色列表，也不在重建失败后发送失效旧角色列表**，避免污染角色和聊天自动加载状态。原生读取不受桥接 fast 期限限制。
- **保存请求完全使用原生路径**，桥接与 SW 不做差量保存、失败重试或自动覆盖。后端保留差量保存 API、哈希、用户串行锁和冲突检测，供兼容调用；“保留 API”不代表浏览器默认使用。
- 不再提供模板/XHR 预载、模块改写、扩展生命周期重排等桥接入口。`moduleProxyEnabled` 归一化为 false；旧 toolbox 模块代理 URL 保留兼容服务，供现有安装进入面板做一次性修复，不能替代迁移。
- 默认无需注册 SW，面板移除注册入口。`sw.js` 仍可被旧 toolbox 客户端更新：新兼容 worker **没有 fetch 监听器**，核心模块、导航、读写全部原生透传。它不自动注销任何 worker，不清理其他缓存。用户可确认注销准确识别的旧 SW。

这是明确的性能取舍：不追求极限首屏加速，优先让后端删除、接口故障不再成为原生核心启动的持久依赖。不会再通过模块代理修复 `dynamic-styles`；相关独立核心/主题兼容问题应单独处理。

## 来源与保留功能

迁自本机 `cocktail` 0.1.17、`cocktail-plus` 0.1.24，作者 Limerence。出处与许可边界见 `features/tomatojuice/PROVENANCE.md`。未修改源插件。

| 功能 | 当前状态 |
|---|---|
| 启动列表快照、分批聊天渲染、预设/世界书/正则拖拽、UI 动画、世界书面板精简 | 保留前端优化器；列表快照单次消费 |
| 正则刷新调度 | 仅可判定 ST >= 1.14 时加载 |
| 聊天保存解除 UI 阻塞 | 保留 UI 优化，实际保存使用原生请求 |
| HTML 渲染缓存、预设面板优化实验 | 未加载 |
| 角色 shallow 持久缓存、version 缓存 | 可选只读桥接使用；按用户隔离、按文件签名失效 |
| 角色读取/编辑、settings/get、settings/save、chat-save、recent-chats fast APIs | 保留后端兼容实现及安全验证，不再自动桥接 |
| 模块代理 URL | 仅迁移兼容，不再生成持久代理入口 |
| 浏览器日志 | 不再由桥接挂全局采集；现有用户隔离日志 API 保留 |
| 上游自动更新/安装 shell、自动 patch 核心 | 不执行；使用酒馆原生前端更新及手动后端部署 |

## 角色缓存、关闭与大卡库

- `cacheCharactersAll: false`：新版桥接直接透传原生角色列表，不再经 fast 接口转发。`cacheVersion` 独立控制 version。`enabled: false` 停用两者；端点关闭时自动/手动预热均跳过。
- `/probe` 与 `/status` 提供不含用户数据的 `readPolicy`。前端探测/刷新状态时同步当前桥接策略；重复加载新版桥接只更新策略，不叠加 fetch 包装。无此策略的旧后端不再由新版前端主动安装晚到桥接或预热，保留原生行为。
- 旧页面仍访问已关闭 fast 端点时，后端返回 503 和旁路标记，**不在后端再发起原生请求**。新版桥接据此禁用该路由，浏览器回退原生。已经运行的旧版脚本无法就地替换：更新后端、重启并刷新所有标签页；不要把“更新磁盘上的文件”当成已更新浏览器中的代码。
- 配置文件仍为后端目录的 `tomatojuice.config.json`，启动时读取，不是文件热加载。修改配置后需手动重启后端，刷新页面；面板不会擅自重启服务。
- PNG 解析缓存与聊天统计分离，按用户、目录、文件元数据隔离和复用。聊天变化仍更新 `date_last_chat` / `chat_size`，但未变化的卡片无需重复读取 PNG。角色新增、修改、删除、重命名及外部文件修改仍通过每次元数据扫描识别，不依赖 TTL 或文件监听猜测新鲜度。
- 元数据扫描异步、并发有上限；同轮构建复用前置快照，完成后再次校验签名及失效代次。签名变化、缓存清理、配置改变或构建超时后，不提交或返回过期构建结果。热缓存仍需要元数据扫描，**不承诺零 I/O 或固定毫秒数**。
- 聊天统计匹配原生的目录直属条目元数据，包括非 `.jsonl` 条目；不解析聊天正文、不递归扫描其内容。孤立的、没有对应角色卡的聊天目录不影响该列表。
- 角色解析/统计内存缓存有用户数、条目数与估算字节数上限；新持久缓存使用 schema 2，旧缓存不作为新格式读取，无需删除用户数据。增量解析结果只驻留内存，进程重启后按需重新建立。

## 部署

1. 更新前端 `st-toolbox`。TS 修改后执行 `npm run build:tomatojuice`；普通使用无需构建。
2. 手动复制整个 `server-plugin/st-toolbox-server` 到 `SillyTavern/plugins/st-toolbox-server`，升级保留目标 `tomatojuice.config.json`。不是复制到前端 third-party 扫描目录；后端无额外运行依赖。
3. 酒馆配置启用 `enableServerPlugins: true`，由用户手动重启。
4. 打开“扩展设置 → ST Toolbox → 茄汁 / tomatojuice”。后端不可用仍保留原生请求。无需安装 HTML 入口或注册 SW；需要只读加速时可选“安装／修复首屏接入”。

安装/撤销/清理 HTML 均影响所有用户，需要管理员身份、有效酒馆 CSRF 会话和明确确认。只读检查无需修改文件；写请求不接受路径/HTML，不执行命令，不自动重试、刷新或注销 SW。先备份再原子写入，备份位于 `data/_st-toolbox/html-backups`；全局锁防并发，重复执行幂等。符号链接、重复/不成对标记、未知脚本或不能核对的代理源均拒绝修改。

## 旧 cocktail / cocktail-plus 迁移顺序

**先恢复启动入口，再删除旧后端，不要“先删后端再试”。**

1. 停用旧 `cocktail` / `cocktail-plus` 前端，避免两套优化叠加。茄汁检测冲突后不加载优化器，但迁移管理区仍可使用。
2. 在“迁移诊断与可选只读加速”点击 **检查首屏状态**，确认是否仍有旧 HTML 核心代理依赖。点击 **清理可识别旧 HTML**：确认后备份并移除已知旧 bridge/import map，将带原始源属性且 URL 精确匹配的核心代理标签恢复为原生 URL。未知结构不会猜测；先对照备份人工处理。
3. 点击 **检查旧前端 / SW**。点击 **确认注销已识别 SW** 会列出 URL 后确认，只处理同源、准确路径 `/api/plugins/cocktail-plus/sw.js` 或 toolbox 模块 `/sw.js`；有未知 waiting/installing worker 的注册也不动。不接管旧 cocktail SW，不清理其他 SW 或缓存。
4. 保存当前工作后刷新，确认原生核心可用，才删除旧后端。需要时再安装新版可选只读桥接。

旧 SW 自身可能已有 404 原生回退，**不能把黑屏一概归罪 SW**。旧 HTML 中 `script.js` / `i18n.js` 若指向 `/api/plugins/cocktail-plus/module?...`，删除旧后端会在工具箱代码运行之前 404，面板根本没有执行机会。

### 已黑屏或新面板无法启动：一次性离线恢复

新代码无法凭空修复已经删除的旧后端或尚未更新的浏览器 SW。可临时恢复旧后端进入旧工具撤销，或由用户离线运行随附 CLI（无需部署后端，不会重启）：

```powershell
# 在酒馆根目录，路径也可指向前端仓库随附的脚本
node plugins/st-toolbox-server/tools/early-bridge.mjs status .
node plugins/st-toolbox-server/tools/early-bridge.mjs cleanup-legacy . --apply
node plugins/st-toolbox-server/tools/early-bridge.mjs uninstall . --apply
```

`cleanup-legacy` 只清理可识别 cocktail-plus HTML；`uninstall` 撤销 toolbox HTML。CLI 与面板共用验证、备份和锁。异常结构应按备份手动核对，不要直接覆盖整份 HTML 丢掉后续编辑。CLI 不会注销浏览器 SW，需在浏览器开发者工具 Application → Service Workers 中核对准确 URL 后注销旧 worker。保存工作、完成 HTML 修复后再刷新。

## 卸载新版

优先撤销可选 HTML 入口、确认注销已识别 SW，再删后端/前端。即使新版桥接后端先消失，async 脚本加载失败不会阻塞原生模块；已加载桥接读请求限时旁路；新版 SW 不拦截网络。**这一保证不追溯至尚未迁移的旧 HTML / 旧 SW。** 关闭前端开关不会自动撤销全站 HTML 或已运行的脚本。

## 验证与边界

自动化覆盖后端删除、404/500/502/503、网络/响应体超时、非 JSON、旧空列表状态头、调用者 abort、只读熔断、保存不重试、原生模块入口、旧 HTML 受保护清理、备份/幂等、CSRF/管理员/路径边界、多用户缓存及后端保存冲突。SW 测试覆盖兼容激活/无 fetch 监听、精确 URL 清理且不动其他 worker。

在保留本地测试文件的开发环境中，完整测试用 `npm test`；另有 `tests/*.test.mjs` 对话导出/原生控件回归。浏览器控件测试使用临时测试页面，不改运行酒馆 HTML。

**未在运行中酒馆部署、重启或做真实首屏端到端验收。** 仍需用户验证：真实大卡库冷启与自动加载聊天、特殊卡格式与角色变更、长单聊/群聊保存、九个优化器对当前 DOM 的适配、多标签/多用户、反向代理/HTTPS/CSP、旧浏览器 SW 实际更新生命周期。原生服务自身故障不会被插件隐藏；不把源码/VM 测试等同现场恢复验证。
